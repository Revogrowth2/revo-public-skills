# Segurança e privacidade

O conteúdo público ensina um método; não hospeda os Brains privados dos usuários. Não envie credenciais, tokens, contexto de cliente, backups do cofre ou dados pessoais para Issues, PRs ou anexos.

Se uma credencial vazar, revogue/rotacione no serviço emissor e revise uso/permissões. Apagar a linha ou o arquivo não invalida a credencial nem remove cópias/histórico. Limpeza de histórico exige procedimento específico; não substitui revogação.

Para reportar uma vulnerabilidade deste projeto, use **Security → Report a vulnerability** se o recurso estiver disponível. Caso não esteja, abra uma Issue sem detalhes sensíveis pedindo um canal privado. Nunca publique um segredo para provar o defeito.

`.gitignore` reduz erros comuns, mas não é controle de acesso, criptografia, scanner completo ou proteção contra leitura pelo agente. Cofre de senhas e permissões continuam necessários.
