# Como contribuir

Use exemplos fictícios. Informe produto/superfície, sistema operacional, versão, passos, esperado e obtido. Diga se foi revisão documental ou teste executado. Não anexe seu Brain preenchido.

Uma skill deve ter nome e descrição claros, recursos autocontidos, instruções sem dependência de caminhos privados e licença compatível. Referências oficiais ajudam a manter diferenças entre produtos corretas.

Revise links relativos, instalação, ZIP com a pasta da skill na raiz e casos de projeto existente, navegador sem acesso a disco, duas frentes e conflitos de edição. Preserve autoria e licença. Não prometa suporte a um sistema apenas porque o comando parece portátil.
